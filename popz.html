POPz: Pop Music Party Game

A party game for iPhone that I designed, built and am publishing on my own, under my studio name Brado Games.

Role
Solo developer
Engine
Unity 6, C#
Platform
iPhone
Status
Coming soon to the App Store

The game

Players pass one phone around a party. Each card is a pop music prompt from one of four eras: the 90s, 2000s, 2010s or 2020s. A game is 40 cards long and ends with a "most picked" screen, so everyone sees who got called out the most.

What I did

  • Designed the game and wrote all 257 prompts
  • Programmed it in Unity 6 and C#, including New Rule cards that stay active for a few rounds
  • Made the pop-art UI, app icon, splash screen and sound effects
  • Tested every build on a real iPhone
  • Wrote the privacy policy, App Store screenshots and store listing

Problem I solved: repetitive cards

In playtests, too many prompts were the same idea: "name five songs by...". I rewrote them into different kinds of challenges, like a timed Song Rush, fandom battles, humming a song for others to guess, and song charades. Now every card feels like a small surprise.

Problem I solved: building for iPhone without a Mac

iOS games normally need a Mac with Xcode, and I work on a Windows laptop. I set up a GitHub Actions workflow: I export the project from Unity, upload it, and a cloud Mac builds the app for me. I install that build on my iPhone to test. The same workflow will create the signed builds for TestFlight and the App Store.

What I learned

  • Content design matters as much as code in a party game.
  • Testing on a real phone catches problems the editor never shows.
  • Shipping a game includes a lot of work outside the engine.
